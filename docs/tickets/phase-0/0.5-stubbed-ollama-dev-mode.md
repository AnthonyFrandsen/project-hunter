# Phase 0.5 — Stubbed/Mocked Ollama Response Mode

**Draft Number:** 1
**Ticket Status:** Draft — first draft, still being refined

## Goal
Let development on Phases 1–3 (server core, extension scaffold, listing ingestion) proceed end-to-end without depending on the real Claude Code CLI + Ollama stack on every iteration.

## Description
Add a stub/mock mode that returns canned Ollama-style responses in place of the real local model call. This lets the surrounding pipeline logic — queueing, progress reporting, file I/O — be built and tested before the real integration (Phase 4) is wired in.

This was raised as `docs/open-questions.md` OQ11 and confirmed by the user as a suitable development scaffold.

## Reference
- `docs/roadmap.md`, Phase 0, item 0.5
- `docs/open-questions.md`, OQ11
- `docs/prd.md` §9 (Development/testing)

## Acceptance Criteria
- [ ] A mock/stub mode exists that can stand in for real Ollama responses.
- [ ] Mode is toggleable (e.g., via env var) without code changes.
- [ ] Documented as a dev-only scaffold, not shipped as a user-facing feature.
